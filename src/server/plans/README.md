Owner area: plans. The one writer of Glim plans, and the autopilot's scanner and runs; no PayPal.

- `apply.ts`: `applyAutopilotChange`, `prepareAutopilotRaise` (autopilot), `confirmPlan` (a `plan_started` action, or `plan_edited` when it replaces a running plan), `skipLot` (the guest). Each is one transaction (`withPlanTransaction`, `db.ts`): the paddle's running plan row, then the lots it touches in id order, then the engine through `createTransactionStore`, then the records. The engine change and its records commit together or not at all.
- `proposals.ts`: a proposed plan row with the card the guest saw (`proposal.card`); `confirmPlan` reads it back with `planCardSchema`. A new card supersedes one still waiting, and `alsoWrite` lets the chat commit the transcript with it.
- `raise-offer.ts`: `loadOpenRaiseOffer`, the raise Glim prepared that the guest can still take (V3), and `dismissRaiseOffer`, its "Not now". The chat's raise route opens a PayPal window only for an open offer's stored amount. An offer belongs to the plan it was prepared for (`glim_actions.plan_id`): an edit that replaces that plan ends it here, in `pendingRaise` (`context.ts`) and in the prepare step's own "one pending raise" check, so the guest is never asked to hold more for a plan they changed.
- `pause.ts`: `pausePlan`, `resumePlan`: the plan's status and version in their own transaction, then the engine's `pauseLimits` or `resumeLimits`. That order is what fences an autopilot decision in flight.
- `scan.ts` (`scanFacts`, `scanClosingSoon`, `claimDue`, `releaseClaim`, `requeueClaim`), `context.ts` (`loadAutopilotRead`), `run.ts` (`runAutopilot`, `autopilotGate`), `task.ts` (`createAutopilotTickTask`, registered in `src/instrumentation.ts`), `usage.ts` (`tokensToday`, the one daily count chat and autopilot share), `runs.ts` (run rows and the "Deciding…" rows).

The decision itself is pure and lives in `src/server/glim/autopilot/` (options, validator, rule, brief, copy); the model never gets a tool, and every change goes through `createLimits`, which refuses anything over the hold. Spec: `docs/planning/glim-autopilot.md`. Tests: `npx vitest run tests/integration/plans tests/unit/glim/autopilot`.
